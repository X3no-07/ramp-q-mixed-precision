# 研究方向导航

当前主线是：找出量化使哪些具体目标消失，检查哪些模块的精度干预与失效相关，再恢复这些模块并验证同一目标是否回来，同时扣除对其他稳定目标造成的附带漏检。工作名为 RAMP-Q。

本入口按2026-10-23已有记录整理。它区分研究动机、已验证事实和下一阶段方案，不把预期贡献写成已经证明的创新性。

## 当前可以支持的判断

Gate0 的 RUOD-R 模拟实验支持当前设置下的目标级量化失效与恢复信号；有标签传统敏感度方法与目标级候选出现选模碰撞，不能据此宣称一种新的选模算法已经胜出。

Gate0.5 已完成限定部署配置的150图评估：FP16 到全 INT8 新增漏检44个，G1 恢复救回40个并使3个稳定目标漏检。限定集合净恢复为+37，总命中相对全 INT8 增加34。该恢复存在性判据通过，但原完整 PyTorch/ORT 数值护栏仍为 `FAILED_UNCHANGED`；诊断复用集合不构成新鲜独立确认集，也不能据此证明纯 G1 算术因果或速度能耗优势。详见[报告39](../工程/报告/39_Gate05_150图完整验收结果.md)。

Gate1 的30轮候选训练完成，但全 FP32/FP16 固定数值检查失败。后续混合精度原型、AP/AR 合成原生对照、合成训练及 FP32 保存接入均取得各自工程结果；这些检查不替代真实独立数据验收。最新阶段见[报告50](../工程/报告/50_Gate1_合成训练管线与FP32保存接入验证.md)。

## 下一阶段要回答的问题

1. 在成员、ignore 处置、训练参考和候选预算都事先固定后，能否得到合格的真实数据科学浮点基线？
2. 逐目标破坏与恢复信号能否在 VisDrone 独立确认集复现，目标级信息是否相对传统基线增加价值？
3. 锁定候选后，真实部署能否兼顾检测质量、延迟、显存和能量成本？

独立确认集保持封存，不能用于调阈值、选模块或挑训练候选。历史方案、工程通过、科学验收和部署性能应分别报告。
