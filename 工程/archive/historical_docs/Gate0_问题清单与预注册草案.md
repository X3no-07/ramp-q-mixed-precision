# RAMP-Q Gate 0：目标级量化失效与模块恢复最小验证

> 状态：**问题确认与预注册草案，尚未开始正式实验**  
> 创建日期：2026-09-10  
> 目标：用最小成本判断“根据被救回的弱小目标选择 FP16 模块”是否有真实、可重复、优于普通层敏感度的研究信号。  
> 证据边界：Gate 0 只验证机制可行性，不声称达到 SOTA，不声称完成 Jetson 部署，也不把 PyTorch 假量化结果写成真实 TensorRT INT8 性能。

## 1. 这次 Gate 要回答的唯一核心问题

全 INT8 导致一批原本能被高精度模型检测到的目标漏检后：

1. 这些新增漏检是否明显集中在小、低对比度或低置信余量目标上？
2. 每次只改变一个模块的精度时，是否存在少数模块能够稳定导致或救回这些具体目标？
3. 根据“救回哪些目标”选出的模块，是否优于随机选层和普通总体敏感度选层？
4. 这种救回是否能在独立留出集上复现，而不是只对用于选层的图片有效？

若上述问题没有得到支持，就停止 RAMP-Q 主假设，不继续包装成论文方法。

## 3. 推荐的最小实验范围

### 3.1 推荐决策

先在已有 RUOD-R + YOLO11n 上做 **Gate 0 机制筛查**，因为数据和训练权重已经具备；通过后再进入 VisDrone 主基准。

这样做的含义是：

- RUOD-R Gate 0：回答方法有没有信号；
- VisDrone Gate 1：回答非水下主任务上能否复现；
- Jetson Gate 2：回答真实硬件收益是否成立。

RUOD-R 通过不等于论文成立；但 RUOD-R 都无法通过时，没有必要立即投入 VisDrone 训练和 Jetson 部署。

### 3.2 Gate 0 的量化证据

推荐使用 PyTorch 静态 W8A8 假量化进行模块隔离：

- 权重：INT8 对称、逐通道量化；
- 激活：INT8、固定校准尺度；
- 校准集：从训练集固定抽取，不能使用最终留出评估图片；
- 每次干预时冻结权重、校准尺度、输入和后处理参数；
- 所有实验共享同一套预测与匹配代码。

这一步用于低成本验证因果结构。它不能替代后续 TensorRT 和 Jetson 实测。

## 4. 隔离实验设计

设：

- `F`：全高精度参考模型；Gate 0 中优先使用 FP32 作为稳定参考；
- `Q_all`：全部候选模块使用 W8A8；
- `Q_j`：只有模块组 `j` 使用 W8A8，其余保持高精度；
- `R_j`：从 `Q_all` 出发，只有模块组 `j` 恢复高精度；
- `R_{j,k}`：从 `Q_all` 出发，同时恢复模块组 `j` 和 `k`。

### 4.1 模块组第一层划分

第一轮按功能分组，不直接穷举几十个卷积层：

| 组 | 暂定范围 | 目的 |
|---|---|---|
| G1 | Stem 和早期高分辨率 Backbone | 检查原始细节是否被量化抹除 |
| G2 | Backbone 中层 | 检查局部纹理和中层语义 |
| G3 | Backbone 深层 | 检查高级语义表示 |
| G4 | Neck 自顶向下融合路径 | 检查高低层信息融合 |
| G5 | Neck 自底向上融合路径 | 检查定位与语义再聚合 |
| G6 | P3 小目标输出分支 | 检查小尺度预测专用路径 |
| G7 | P4/P5 输出分支 | 作为中大目标路径对照 |
| G8 | 分类与回归输出层 | 检查置信度和框回归量化敏感性 |

模型实际结构解析完成后，将给出精确到 Ultralytics 模块编号的互斥、完备映射。若某一组过大，再只拆分排名靠前的敏感组。

### 4.2 双向干预

对每个模块组都必须做两种实验：

1. **单组降级**：`F → Q_j`，验证只量化该组是否会让目标消失；
2. **单组恢复**：`Q_all → R_j`，验证只恢复该组是否能让目标回来。

只有恢复实验，不能证明该模块就是原始失效来源；只有降级实验，不能证明它在全 INT8 环境中具有实际救回价值。

### 4.3 组合干预

完成单组扫描后，只对排名最高的 3 个模块组测试：

- 三个两两组合；
- 一个三组组合；
- 相同高精度计算占比下的随机组合对照。

这样可以发现“单组不能救回，但两个组一起可以救回”的误差累积和模块交互，同时控制实验量。

## 5. 目标级判定规则

### 5.1 主要匹配

- 同类别；
- 预测框与真实框 IoU ≥ 0.50；
- 主要运行阈值：置信度 ≥ 0.25；
- 诊断预测保留至置信度 ≥ 0.001，用来区分“完全没有候选框”和“候选框跌破运行阈值”。

### 5.2 新增漏检

`int8_added_miss` 定义为：

```text
F 对该真实目标匹配成功，Q_all 对同一目标匹配失败。
```

### 5.3 救回

模块组 `j` 救回目标 `i` 定义为：

```text
目标 i 属于 Q_all 的新增漏检集合，且 R_j 对目标 i 恢复同类别、IoU ≥ 0.50、置信度 ≥ 0.25 的有效匹配。
```

必须同时记录救回来自：

- 分类置信度恢复；
- 边界框 IoU 恢复；
- NMS 保留关系变化。

## 6. 数据隔离与防止结果泄漏

### 6.1 三份数据用途

- 校准集：只从训练集抽取，用于确定激活量化尺度；
- 选择集：从验证集确定模块排名和前 3 个候选组；
- 留出集：在模块选择完成前不可用于选层，只用于验证救回是否复现。

### 6.2 固定原则

- 图片列表和随机种子在实验前写入清单并保存哈希；
- 所有模型变体使用相同输入尺寸、预处理、阈值、NMS 和匹配算法；
- 不允许为某个模块单独更换校准集；
- 不允许用留出集反复修改分组或阈值；
- 模块隔离阶段不重新训练，否则无法区分精度干预与训练适应的影响。

## 7. Gate 指标与暂定阈值

这些阈值将在收到用户确认后冻结，实验完成后不得修改。

### 7.1 进入模块扫描的最低信号

在扩大样本直至完整 RUOD-R 验证集后：

- `Q_all` 至少产生 50 个 `int8_added_miss`；
- 新增漏检在小目标或低对比度风险组中的优势比建议 ≥ 1.5；
- 若完整验证集仍少于 30 个新增漏检，直接判为 `STOP：信号不足`；
- 若有 30–49 个，只允许给出 `PIVOT/INCONCLUSIVE`，不得给出强因果结论。

### 7.2 主要成功指标

1. **目标救回率**

   ```text
   RescueRate(j) = 被 R_j 救回的新增漏检目标数 / Q_all 的新增漏检目标总数
   ```

2. **风险加权救回率**

   小、低对比度和低置信余量目标获得更高权重，但权重公式必须在查看模块结果前冻结。

3. **同预算优势**

   所选模块组合必须与相同高精度计算占比的随机组合及普通总体敏感度方案比较。

4. **稳定目标保持率与净救回**

   恢复模块可能救回一批目标，同时让另一批原本稳定的目标消失。因此必须同时报告：

   ```text
   稳定目标保持率 = 恢复后仍命中的原稳定目标数 / 全INT8原稳定目标数
   净救回 = 救回数 - 恢复操作导致的附带新增漏检数
   ```

### 7.3 暂定通过标准

同时满足下列条件才进入 VisDrone Gate 1：

- 最佳单模块组在留出集救回至少 15% 的新增漏检目标，且绝对数量不少于 20；
- 最佳模块组在单组恢复排名中位于前 1，在单组降级排名中至少位于前 3；
- 前 2～3 个模块组合的风险加权救回率，相对同预算随机组合均值至少提高 20%；
- 稳定目标保持率至少 98%，且净救回为正；
- 结果不是只由一个类别或少数几张图片贡献；
- 恢复组合的高精度计算占比暂不超过总 MACs 的 25%；
- 在留出集上仍保持同方向，而不是只在选择集有效。

### 7.4 停止或转向

- `STOP`：完整验证集新增漏检少于 30；
- `STOP`：没有任何单模块或小组合产生稳定救回；
- `STOP`：必须恢复大部分模型才能救回，失去边缘部署价值；
- `PIVOT`：能救回，但普通总体敏感度方案同样好或更好；
- `PIVOT`：救回只来自阈值波动，IoU、原始候选和 NMS 分析不支持稳定机制；
- `GO`：双向隔离、留出复现和同预算对照均通过。

## 8. 推荐执行顺序

1. 新建隔离工程和可用 Python 3.12 环境；
2. 生成不含旧绝对路径的新 RUOD-R 数据配置；

7. 若不足 50 个，扩大至完整验证集；

9. 在选择集确定前 3 组，运行组合与随机对照；
10. 锁定方案后只运行一次留出评估；
11. 生成 CSV、JSON、日志、案例图和最终 `GO/PIVOT/STOP` 报告。
