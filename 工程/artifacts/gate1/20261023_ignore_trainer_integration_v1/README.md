# Actual criterion and Trainer integration, synthetic scope only

The new `scripts/gate1_ignore_trainer.py` integrates the reviewed ignore-negative BCE into the installed Ultralytics 8.4.142 detection criterion, random-initialized `DetectionModel`, and actual `DetectionTrainer` lifecycle. It does not modify the installed library or any previous experiment.

The classification intervention masks all class channels at unassigned anchor centers inside publisher-ignore boxes; every TAL-positive row is retained. The pinned TAL invocation, box/DFL path, target-score denominator, loss gains and batch multiplier remain unchanged. The TAL empty-GT path returns a floating all-zero foreground mask; the adapter converts only the strict helper's mask argument to boolean, leaving the returned assignment tuple and native regression path unchanged.

The constructor is `RestrictedIgnoreTrainer(training_contract=..., model_cfg=dict, dataset_factory=None, fp32_capture_callback=None, overrides=..., _callbacks=...)`. The contract schema is `rampq.gate1.synthetic_ignore_trainer_contract/v1`; it requires `synthetic_only=True`, `class_count`, a `names` list, the exact geometry `restricted_options`, and `datasets` with `train` and `training_val` entries containing `manifest_path` and `manifest_sha256`. Each manifest must additionally use `rampq.gate1.ignore_dataset_manifest/v1` and `data_role=synthetic_only`. The default factory instantiates the new `RestrictedIgnoreDataset`; an optional custom factory is intended for controlled integration tests and receives `mode`, `img_path`, `trainer`, and `batch` keyword arguments.

Only a one-epoch, CPU, explicit-batch synthetic run is supported. AMP, pretrained/old checkpoint loading, automatic batch sizing, recovery, multiscale, mosaic and unreviewed transforms are rejected. `nbs=batch` ensures the framework takes an optimizer step each batch. Explicit loader/LetterBox/flips are supplied by the new Dataset rather than the ordinary probability-zero augmentation pipeline. No real dataset, selection set, holdout, old checkpoint or GPU input is read by these unit tests.

`preprocess_batch` reuses the native uint8-to-FP32 image normalization and transfers explicit ragged FP32 sidecars to the model device. Missing geometry, dtype drift, and missing image identities fail rather than becoming empty ignore regions. The criterion exposes `last_mask_receipt` and `observed_batches`, containing detached scalar diagnostics only.

Task validation is deliberately disabled: `get_validator` is an empty lifecycle object, `validate` returns the lifecycle sentinel `({}, 0.0)`, and `final_eval` records `SMOKE_NO_TASK_AP`. That zero is not a measured metric. This avoids the framework's final half-checkpoint/fused validation while proving the train/save lifecycle. No AP, real training, generalization, deployment or scientific Gate1 claim follows from this module.

`save_model` supports a direct `fp32_capture_callback(trainer)` before parent FP16 serialization. The separate `FP32LiveCaptureMixin` can instead be placed first in the MRO; in that mode leave the direct callback `None`, avoiding duplicate capture. The framework may write new synthetic compatibility checkpoints in FP16. They are not substitutes for the separate live-FP32 capture.

The final CPU tests pass 51/51. Four real random-model comparisons cover empty ignore with and without GT and class weighting: loss components, every model parameter gradient and the input gradient are bitwise equal to the native criterion. Additional actual TAL tests preserve positive classification gradients and regression loss while removing ignored-background score gradients; all-ignore/no-GT yields zero loss and score gradients. The final JUnit XML binds the observed test outcomes. It does not represent the later end-to-end Trainer run, which the parent records separately.
