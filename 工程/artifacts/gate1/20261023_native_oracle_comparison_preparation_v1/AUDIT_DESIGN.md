# Native synthetic oracle audit design

This preparation reads only pinned source text, the 20 synthetic fixtures, and their existing regression tests. It does not read images, dataset annotations, model weights, Selection outputs, or Holdout contents. No native execution or Python-versus-native equivalence is asserted by this document.

## Source and invocation boundary

The frozen `run_synthetic_oracle.m` calls the original `dropObjectsInIgr` for every image in all 20 fixtures, the original `evalRes` for all 10 categories in each of the 5 matching fixtures, and the original `calcAccuracy` in all 11 aggregate fixtures. `createIntImg`, `compOas`, and `VOCap` are invoked by those unchanged official functions. The 4 region fixtures preserve the filtered/prepared matrices without asking the runner to compute metrics. The runner asserts `which` for all 6 called official function names equals the pinned official `utils` location. No direct execution of `evalDET`, `saveAnnoRes`, `findImageList`, or `displayImage` is needed or allowed.

The old Python launcher only permits new children inside its own now-frozen preparation directory. It must not be reused to write a new attempt there. A separate wrapper should run the same frozen MATLAB function with an output directory in a new artifact tree. Before execution, the wrapper should verify source/runner/fixture hashes and use a clean native function path. Its native session should confirm `mean2` comes from the real native image package or MATLAB installation; a handwritten replacement is outside the intended test.

## Integrity checks for a future auditor

1. Bind the exact source-manifest SHA and all 11 source members, the frozen runner SHA, fixture-contract SHA, and fixture SHA. Bind the wrapper, native executable, command, return status, dependency paths, console, MAT and JSON output identities in the launch receipt. Verify native-reported runtime version and resolved functions against the independently recorded wrapper receipt.
2. Require exactly the 20 fixture IDs in their original order and the original kind/purpose values; 11 aggregate, 4 region, 5 match. Require every case status to be `EXECUTED_NATIVE_SOURCE`, `case_errors=0`, one intermediate per original synthetic image, and the original scope flags to remain false for real data, model execution, and official AP-equivalence certification.
3. Treat MAT `-v7` output as authoritative for dimensions and exceptional numeric values. Load without squeezing numeric matrices. Require filtered/prepared matrices to be two-dimensional with 8 columns, including empty `0x8`; require per-category matcher GT `m x 5` and DT `n x 6`, including empty `0x5` and `0x6`. Singleton object/cell containers may be unwrapped only where the fixture requires exactly one object. Do not reshape malformed empty numeric arrays to make them pass.
4. Require each of the 5 matching images to report exactly categories 1 through 10, preserving that order. Matcher rows must retain the input geometry/score values as row multisets; score order must be nonincreasing, positive GT must precede ignored GT, and match flags must remain in the native `-1/0/1` domain. Do not impose a Python-specific tie ordering. Ground-truth score inversion must use the original filtered score masks; score-0 GT are retained and marked ignored.
5. Require exactly the seven named AP/AR metrics in aggregate records and no invented metric fields for region or match records. Metric values must be numeric scalars, finite or NaN, never Inf. No manually written expected AP/AR values are used. Preserve repeated `evalClass` entries, original submission order before maxDets, score-0 denominator behavior, raw coordinates, and the exact runtime's sort-tie behavior.
6. Compare JSON to MAT as a serialization copy, permitting only documented serialization losses: empty array dimensions, singleton row/cell containers, and NaN encoded as JSON null. Match original finite numbers and strings, preserving ordered rows/cells and duplicate rows. JSON null must not be accepted for a finite MAT number. The MAT file remains the reference when JSON cannot represent a dimension.

An auditor pass would certify saved native synthetic-output integrity/structure only. It would not certify the existing Python matcher, implement full Python AP, validate real-data accuracy, qualify a model, change either precision guard, or pass Gate1.

## Synthetic auditor tests

Tests should construct clearly labelled fabricated MAT/JSON bundles solely to exercise the auditor. They must never be presented as oracle outputs or official AP values. Useful negative cases include altered source hash, shadowed function path, missing/duplicate/reordered fixture, missing image/class, nonzero native error count, zero return status with missing MAT, `0x0` replacing `0x8`, squeezed matcher matrices, wrong score-inversion masks, deleted score-0 GT, changed duplicate rows, JSON null replacing finite metric, Inf metric, wrong NaN serialization, and an artificial tie reorder incorrectly rejected by Python-stability assumptions.
