# Controlled live FP32 EMA capture component

This package verifies a CPU-only engineering component. It creates a new random tiny DetectionModel, executes two real SGD steps and two ModelEMA updates, captures its already-FP32 EMA state, and reconstructs the inference graph from a canonical local cfg dictionary with strict state loading. A fixed analytic synthetic input produces exactly matching output tensor values, dtypes and shapes. No old weights or real dataset inputs are read by this example.

The callable `LiveFP32Capture` is suitable for a trainer's pre-save callback. Alternatively, `FP32LiveCaptureMixin` must be first in the trainer MRO, configured on the main training thread, and invokes capture before `super().save_model()`. The two adapters must not both be installed. The framework's ordinary serialization converts a deep copy of EMA to FP16; this hook captures before that conversion and performs no FP16-to-FP32 lifting.

The selected epoch list is fixed explicitly; this component does not choose a best epoch. The hook requires AMP to be explicitly disabled, enabled/eval EMA, completed EMA updates, CPU tensors and all floating tensors already FP32. A nonreentrant hook lock, main-thread requirement and before/after state hashes plus update-counter equality detect supported protocol violations. They do not exclude arbitrary concurrent external writers. The caller must forbid those writers.

The architecture contract pins every installed Ultralytics Python source file through one canonical inventory hash and records package/Torch versions. Only a restricted reviewed graph-module list and cfg keys are allowed; custom activation expressions are rejected. Reconstruction accepts a local cfg dictionary and uses the frozen state writer's restricted `weights_only=True` loader, rather than deserializing a model object. Constructor randomness is isolated from training RNG. A detached model copy is forwarded so live EMA's inference caches are unchanged.

23 synthetic CPU tests passed. The actual terminal completion summary is retained in `test_execution_receipt.json`; a complete raw terminal log was not separately written. The controlled example and nested manifests are retained for direct inspection. Failed captures remain `.pending` and never become a success directory.

This package alone does not execute a dataset-backed Ultralytics Trainer epoch; that integration is a separate root-run check. It does not qualify GPU synchronization, recover old FP16 EMA mantissa, save optimizer/resume state, accept a scientific reference, pass Gate1, or establish AP/deployment/performance results. The original failed FP16 numerical guard remains unchanged.
