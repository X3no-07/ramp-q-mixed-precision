# Gate 0.5：完整参考的数值分歧定位

2026-10-19，接续[完整 q_only_G1 修复候选](28_Gate05_融合前缀与完整候选验证.md)。本轮在原固定 `000020.jpg` 上定位完整 q_all 的参考分歧：卷积后端的微小浮点差异会跨过量化舍入边界并逐层放大；在内存中统一 Conv 和 SiLU 后端后，88 层卷积输出与原 ONNX Runtime 逐字节一致，最终 box 差为 0、score 最大差约 1.31e-7。这是完整模型的反事实诊断，原 PyTorch/ORT 护栏仍失败，Gate 0.5 未通过。

本轮全部在本机 CPU 进行。没有运行板端任务、数据集评估、重新标定或训练。原图、权重、标定、阈值及数值护栏均保留。

## 原失败准确复现

新跑的 PyTorch 与 ORT 主输出分别与原 `20261018_int8/input_v1/local_raw_outputs.npz` 对应数组逐字节一致。ORT 关闭图优化，CPU FP32、四线程，输入预处理保持原样。既有两部分容差均重新检查，未只因第一条断言失败而跳过 score 的统计：

| 主输出部分 | 原 rtol / atol | 最大绝对差 | 超出原容差的元素 |
|---|---|---:|---:|
| xywh | 0.005 / 0.5 | 96.5704651 | 14,204 / 33,600 |
| 10 类分数 | 0.02 / 0.002 | 0.0729592 | 47 / 84,000 |

因此这不是旧日志无法复现的问题。原状态仍为 `LOCAL_QDQ_PREFLIGHT_FAILED`，没有新容差，没有把单图预测数量相同改成数值通过标准。

## 相同卷积输入对照

从原 q_all 抽出 88 个互不依赖的 Conv＋原权重 Q/DQ 子图，保留卷积属性及权重 Q/DQ 节点、初始化器原字节，只把激活 DQ 结果作为显式输入。先回放完整 ORT 自己的激活 DQ 输入，88 个卷积输出均与原完整 ORT 逐字节一致，说明此处没有因拆图改变实测卷积结果。

再喂入 PyTorch 记录的激活 DQ 输入，与原 PyTorch 在同一输入上的卷积输出比较：88 层的最大绝对差为 `2.86102294921875e-5`。相对地，两边各自自由运行时，88 层 Conv 输出差异的最大值是 `3.26055645942688`。

这表明输入同步后，局部卷积差异很小，而自由运行的中间数值会逐层分离。它是诊断回放，不是能独立接受图片的完整模型，不能因此宣布原护栏通过。

独立 weight-only Q/DQ 图检查了 2,576,192 个权重，数值差异为 0；但 87 层合计 28,476 个权重存在位差异，全部是 PyTorch `-0` 与 ORT `+0`。其中 28,473 个来自负值舍入为零，3 个原始权重本来是负零。首边界原报告中 `source_qdq_input_and_weight_bitexact` 使用了允许正负零相等的数值断言，命名过强；原报告保留，补充审查明确更正为数值一致。四组真正 PyTorch 浮点 DQ 与 ORT DQ 各有 459,991 个正负零位差，数值差仍为 0，整数码结论不变。

## 首个量化边界的交叉对照

首 Conv 使用相同输入、量化权重和 bias 时，PyTorch 与 ORT 最大绝对差为 `1.621246337890625e-5`。它们经过首 SiLU 后，在第二 Conv 输入量化处出现 3 / 1,638,400 个整数码分歧，对应量化步长 `0.7481081485748291`。

诊断把 Conv、SiLU、量化器分别交叉换用两个后端：

- 固定 Conv 来源，仅切换 SiLU，第二量化器的整数码不变。
- 切换 Conv 来源，恰好翻转这 3 个位置的整数码。
- 四份 SiLU 输入分别同时送入 PyTorch 与 ORT 量化器，整数码及 DQ 数值各自一致。
- 裸 ORT 卷积以动态 x/w/b 回放，与原前缀首 Conv 输出一致，已检查拆图上下文。

当前固定图的 3 个位置为 `[0,7,105,184]`、`[0,7,176,138]`、`[0,7,177,144]`。其 SiLU 输出除以量化尺度后在 0.5 两侧，距离边界约为 0.5e-6 至 2.4e-6 个整数码单位。原值、浮点 ULP、归一化值和四组交叉结果全部保留。

这支持一个范围明确的因果结论：这 3 处最早的量化码分离由首卷积的浮点计算差异跨过舍入边界造成；该处不是量化器规则不同，也不是切换 SiLU 导致的码变化。它不排除后续网络存在额外的后端差异，不能把三个位置直接等同于完整模型全部误差的唯一来源。

## 末端运算回放

把原图中的所有分组 Conv 输出切为记录的 PyTorch 输出，再从主输出反向裁剪，实际仅需保留三个分类头和 DFL 卷积的四个输出作为输入。剩余 36 个节点不含 Conv，包含 reshape、slice、坐标解码和 sigmoid 等运算。

该末端子图相对 PyTorch 主输出的 box 差异为 0，score 最大差为 `1.3146405919428616e-7`。这说明在记录的末端输入一致时，剩余解码运算没有复现原 96.57 的 box 差异。该子图已切断上游依赖，只用于定位，不能替代原完整模型。

## 完整算子后端对照

在内存中的 PyTorch 模型里，保留原激活 `round/clamp/multiply`、权重、卷积属性和其他 PyTorch 运算，将 88 个 Conv 临时委托给分别建立的 ORT 会话。先使用原完整 ORT 的激活 DQ 输入验证会话上下文。

首次单线程控制在 34 / 88 层有微小差异（最大 1.6212463e-5），因此没有执行该配置的完整反事实，失败控制和代码保留。改用与原完整运行一致的四线程，在新目录进行一次控制复验，88 个会话的输出全部与原 full ORT 及此前 replay 逐字节一致，之后才执行两个完整反事实。

| 参考实现，对照原完整 ORT | box 最大绝对差 | score 最大绝对差 | 原容差下 box / score 越界数 |
|---|---:|---:|---:|
| 原 PyTorch Q/DQ | 96.5704651 | 0.0729592 | 14,204 / 47 |
| PyTorch Q/DQ＋ORT Conv，其余 PyTorch | 0 | 5.6009958e-6 | 0 / 0 |
| 上述实现再统一 ORT SiLU | 0 | 1.3061498e-7 | 0 / 0 |

仅替换 Conv 时，有 84 层 Conv 输出逐字节一致，另外四层位于分类头。第一个额外数值分歧是 `model.23.cv3.0.0.1.conv` 的一个激活量化输入，相差 0.0744243；后续三层也记录完整。再替换 SiLU 后，88 个 Conv 输出均逐字节一致，88 个激活 Q/DQ 输入数值相等，但因正负零不能说输入字节都相同。SiLU 是 1 个共享实例、77 个别名，第二个反事实中实际调用 77 次，未漏掉共享实例。

这形成了完整的定位链：原失败可复现；局部相同输入卷积误差很小；最早三处量化码变化由 Conv 来源决定；完整运行统一 Conv 后大幅收敛；再统一 SiLU 后全部量化卷积输出一致。它支持当前固定图上的完整分歧主要来自后端浮点算术及其量化边界放大，而非本轮已验证的量化参数、权重或量化器规则不一致。不能外推到所有图片、所有算子、TensorRT 引擎或独立数据集。

两种反事实改变了参考实现本身，虽落在原容差内，也不能把原 PyTorch/ORT 记录改成 PASS，或以新实现冒充原 Gate 0 模拟参考。原模型参数、源图和脚本文件前后 SHA 一致，内存中的 forward 在完成后还原。
