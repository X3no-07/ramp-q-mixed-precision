# Gate 0.5：首层量化异常定位

2026-10-19，接续六个冻结引擎工程检查。**已在 Orin / TensorRT 8.5.2.2 的首层小图中确认 Clip→Q/DQ 数值异常，验证固定输入绕行，并验证保留截断语义的首层修复候选。完整检测器尚未修复，Gate 0.5 仍未通过。**

原始失败、量化参数、权重、完整模型、检测阈值和数值护栏均保留。没有运行新的完整检测器、150 张评估、重新标定或性能测试。

## 直接发现

使用原 `000020.jpg` 的同一份 float32 预处理数组，首个激活量化器的原图是浮点 Clip[-1,+1]→QuantizeLinear→DequantizeLinear，scale 为 `0.007874015718698502`，zero 为 0。输入实际范围约 [0.117647,1]，所以这个 Clip 对这份输入逐字节恒等。

CPU ORT 的原图和去掉该 Clip 的配对图输出逐元素一致，正确量化码有 110 个不同值，范围 15～127。

板端原图却把全部 1,228,800 个输入值变成同一反量化常数 `0.007874015718698502`。去掉这个恒等 Clip 后，板端输出与 CPU 逐元素一致。原始 inspector 显示 FP32→INT8 Reformat，然后是带 ±1 原实数边界的 INT8 PointWise Clip。这一数值行为与“原浮点边界被用于整数码域”一致；不是仅凭层名或格式推断。

首层卷积给出同样结果。下面均为同一固定输入、原权重、原 scale/zero、原 Conv 和 SiLU；两个输出分别为卷积激活前与 SiLU 后。

| 板端小图 | 激活前相对 CPU 最大绝对差 | SiLU 后相对 CPU 最大绝对差 |
|---|---:|---:|
| 浮点图，FP32，关闭 TF32 | 0，逐元素一致 | 0.0000104904 |
| 浮点图，FP16，关闭 TF32 | 0.0310437 | 0.0307062 |
| 原 QDQ，开启 FP16 | 40.1015298 | 36.6749301 |
| 原 QDQ，关闭 FP16 | 40.1015298 | 36.6749301 |
| 配对重跑原 QDQ Clip | 40.1015298 | 36.6749301 |
| 配对仅移除首层恒等 Clip | 0.00000762939 | 0.0000143051 |

两个 QDQ 的 FP16 开关对照输出逐位一致。配对重跑原 Clip 也与首轮异常输出逐位一致。每个小图都重复执行两次，各自输出逐位一致，全部为有限值。

配对卷积的实际权重及输入均为 INT8、输出为 FP32，使用同一个 `ampere_fp32_icudnn_int8x4_128x32_relu_small_nn_v1` tactic；没有以改成浮点卷积来恢复数值。权重、bias、scale、zero 和 Conv/SiLU 节点均保留。去掉 Clip 的那份图只删除该节点及两个未用边界常量，并把 ActivationQ 的输入接回 `images`；反向补回这些改动可以恢复原 ModelProto 的完整字节。

还尝试了保留原 ONNX、通过 `precisionConstraints=obey` 请求 Clip 的计算和输出为 FP32。该请求未阻止实际引擎使用上述 INT8 Clip 路径，输出仍为相同错误常数，因此这条设置不能作为已验证修复。

## 数值机制复现

独立 CPU 分析先按冻结参数产生正确激活整数码，再把码错误地 Clip 到 [-1,+1]。由于这份输入的码都大于 1，所有码都会变成 1。

将这些码与原逐通道量化权重做整数累加，再用 FP32 scale 乘积及单次舍入的乘加数值模型还原 bias，**1,638,400 个卷积激活前输出与 native 原始数组逐元素 bitexact，最大差为 0**。普通反量化浮点卷积的最大差约 1.19e-6。正确 CPU QDQ 则与异常 native 相差 40.10。

这解释了保存的孤立首层异常。它不等于读取了 GPU packed scale 或机器指令，也不代表已经证明五个完整引擎所有异常的唯一根因。原完整 q_only_G1 引擎也具有相同的首两个 Reformat / INT8 Clip 记录，但完整引擎随后使用融合 SWISH 和 INT8 输出；本轮额外的激活前输出 tap 会改变这段融合。

CPU 分析与预测数组：`artifacts/gate05/20261019_firstconv_cpu_hypothesis_check/`。分析脚本、原始预测、10 个源文件的前后哈希均保留；之后已将其使用的 native 原始数组 SHA 与完整回传 receipt 再次对上。

## 保留截断语义的修复候选

随后没有把删除 Clip 推广到所有激活，而是尝试一个配对改写：原浮点 Clip→Q→DQ，改为 Q→整数码 Clip[-127,+127]→DQ，保留原 scale/zero。使用全部 88 个冻结激活尺度，各构造 1813 个有限合成值，包括正负数、饱和值、整数/半整数阈值及相邻 float32 ULP。两种图在 ORT_DISABLE_ALL 下逐元素一致，最大差为 0。它是覆盖这些边界的测试，不能冒充穷举所有 float32 或完整模型证明。记录在 `artifacts/gate05/20261019_all_code_clip_scale_equivalence/analysis.json`。

直接交给本机 TensorRT 8.5.2.2 时，INT8 边界常量未被正确解析为数值 ±127，inspector 的边界约为 1.8e-43，小图输出全部变成 0。因此，单纯改 ONNX 图还不能作为可用修复。本轮保留了这个失败版本和原始输出。

再用有效的同一 ONNX 图，在解析后显式把该命名 Clip 的 TensorRT activation alpha/beta 设回原 INT8 常量的数值 -127/+127；其余参数不变。这是明确记录的本后端导入校正，源 ONNX 本身没有再次改动。

- 对首个尺度的 1811 个正负合成样本，输出范围恢复为 [-1,+1]；1801 个样本与 CPU 一致，10 个阈值附近样本相差一个量化步长，最大绝对差约 0.0078740716。没有放宽判据或将其标为全数值通过。
- 把同样改写及导入校正用于固定图片的首层 Conv+SiLU，小图激活前最大差为 7.62939e-6，激活后为 1.43051e-5。主、辅助原始数组都与前面的 no_clip 固定输入对照逐位一致。实际卷积权重及输入仍为 INT8。
- v1 首层 code_clip 包是未上传的准备快照；v2 清理了继承 spec 的旧 CPU 引用及“全部节点字节不变”字段后，才实际上传执行。原权重、bias、scale/zero、Conv/SiLU 和输出声明均保留。

## 接下来怎样验证完整图

当前已有小图修复候选，推进完整 q_only_G1 之前仍需完成：

1. 复核完整图改写及导入校正清单，处理仍存在的后端舍入边界差异；不能把当前算子边界测试当完整迁移护栏通过。
