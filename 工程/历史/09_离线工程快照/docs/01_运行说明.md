# 离线运行说明

以下命令在 Windows PowerShell 执行。进入 09 工程目录后，默认 `python` 用于标准库任务。`run.ps1` 也可通过 `-Python` 指定解释器。

## 核验文件

```powershell
.\run.ps1 -Task verify
```

该命令核验 source_manifest 中列出的每个文件。缺失、大小变化、SHA256 不一致均返回失败。该清单描述的是本次摘取的 98 份文件，不是 07 全部原始回执，也不替代模型正确性检查。

若希望同时检查仍位于旁边的 07 原件：

```powershell
.\run.ps1 -Task verify -SourceRoot '..\07_边缘小目标检测混合精度量化_工程'
```

## 查看当前继承状态和后续方案

```powershell
.\run.ps1 -Task status
.\run.ps1 -Task plan
```

`status` 先核验副本，再读取原收口记录。`live_board_checked: false` 表示这是历史状态，不是实时硬件状态。`plan` 只输出方案草案，不执行它。

## 比较保存输出

独立 Python 环境若已按 `requirements-offline.txt` 配置 NumPy，可直接执行：

```powershell
.\run.ps1 -Task compare
```

本机已有解释器包含 NumPy 2.3.5，可用下面的命令运行，不需要安装新依赖。临时清除 PYTHONPATH 可以避免混入其他项目的包：

```powershell
Set-Location 'C:\Users\lenovo\Desktop\视觉边缘研究\09_边缘小目标检测混合精度量化_工程'
$rampqPreviousPythonPath = $env:PYTHONPATH
try {
    Remove-Item Env:PYTHONPATH -ErrorAction SilentlyContinue
    .\run.ps1 -Task compare -Python 'C:\Users\lenovo\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
} finally {
    $env:PYTHONPATH = $rampqPreviousPythonPath
}
```

跨机器使用时，请在独立的电脑 Python 3.12 环境配置 `requirements-offline.txt`；本次验证环境为 Python 3.12.14 / NumPy 2.3.5，不声称覆盖所有 Python 版本。标准库入口的代码语法兼容 Python 3.8，但上述 NumPy 依赖配置并不针对 Python 3.8。不要将电脑依赖安装步骤直接用于 Jetson 系统环境。

`compare` 会核验图像哈希、冻结 NMS、engine 身份、预测数、原始输出形状和 float32 类型。主输出要求 `[1,14,8400]`，辅助输出要求 `[1,128,20,20]`。前四个通道是框输出，后十个是类别分数；分别统计差异，避免将两种尺度混为一个数值指标。

`anchors_at_or_above_0_25_before_nms` 是 NMS 前候选位置数，不是检测数。`saved_detection_count` 是原报告保存的检测数。跨配置差异仅作描述，没有新设容差、数值通过门槛或归因结论。

## 保存与返回码

```powershell
.\run.ps1 -Task status -Output '.\outputs\my_status.json'
```

目标文件必须不存在；已有文件不会被覆盖。默认只向终端打印。

| 返回码 | 含义 |
|---|---|
| 0 | 本条离线命令完成；不表示 Gate 0.5 通过 |
| 1 | verify 发现文件缺失或哈希/大小错误 |
| 2 | 参数、输入契约、依赖或输出路径等错误 |

## 测试

在具有 NumPy 的上述解释器环境运行：

```powershell
python -m unittest discover -s tests -v
```

测试覆盖证据篡改、路径越界、禁止覆盖已有结果、非有限值/错误形状/错误 dtype/缺失数组键。若没有 NumPy，数值测试会明确跳过；完整测试需 NumPy。
