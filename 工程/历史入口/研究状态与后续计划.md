## 现在已经做完什么

### 1. 建立了Gate 0模拟实验

Gate 0使用RUOD-R水下目标检测数据和YOLO11n轻量检测模型。它不是训练新模型，而是固定一个已经能够检测目标的模型，然后分别观察不同精度和不同模块干预下的检测变化。

Gate 0的主要设置是：

- 500张图片；
- 2,785个标注目标；
- FP32版本正确检测到2,293个目标；
- 全W8A8后有165个目标变成新增漏检；
- Selection使用350张图片寻找信号；
- Holdout使用150张图片，在规则冻结后检查是否复现。

这里的“新增漏检”有严格含义：同一个目标在FP32中被正确检测到，但在全W8A8中没有被检测到。FP32本来就没有检测到的目标不能算成量化造成的漏检。

### 2. 完成了模块级破坏—恢复实验

YOLO11n的卷积层被按网络结构分成G1到G8。我们做了两种相反方向的干预：

```text
q_only:G1：只把G1量化，其他模块保持高精度
r_only:G1：全模型量化后，只把G1恢复成高精度
```

第一种实验问“量化这个模块是否足以让目标消失”；第二种实验问“恢复这个模块是否能让目标回来”。只有同一个目标在两个方向上对应，归因才有较强的解释力。

G1的结果在Selection和Holdout中都比较稳定：

| 配置 | Selection净救回 | Holdout净救回 | 说明 |
|---|---:|---:|---|
| G1恢复 | +81 | +36 | 较低计算成本下有明显恢复信号 |
| G1+G5恢复 | +92 | +38 | 多恢复一个模块，但成本更高 |

G1恢复在Selection中有69个、Holdout中有25个“双向同目标”。这表示同一个目标确实同时满足“相关模块被量化时消失”和“相关模块恢复时回来”。

“净救回”不是只看找回多少。例如Selection的G1找回94个原先因量化漏掉的目标，同时使13个原本稳定检出的目标漏掉，所以净救回是94−13=81。它不是mAP，也不直接等于检测精确率。这里“正确检测”的规则是同类别、一对一匹配、IoU至少0.50，主置信度阈值0.25；比较时不能随意改变阈值。

### 3. 做了随机和传统基线比较

G1+G5在当前Selection上通过了三个固定同预算随机组合的对照。这说明不是随便选两个模块都能得到同样结果。

但传统的有标签总体敏感度方法也选出了G1+G5，形成选择碰撞；无标签输出重建误差方法选出了G1+G2，效果也比较接近。因此现在不能把“自动选出了G1+G5”写成已经成立的新选模算法。

这改变的是论文表述强度，不是研究主线。研究主线仍然是：跟踪具体目标的量化失效，验证相关模块的恢复，并研究小目标可靠性。

## 这些结果目前能说明到什么程度

当前结果可以支持：

- 当前模拟量化会使部分具体目标新增漏检；小尺寸、低对比度等风险因素还应单独统计，不能仅凭总数宣称机制成立；
- 少数模块和具体目标的消失存在稳定干预关联；
- 恢复相关模块可以救回部分相同目标；
- 目标级指标比只报告总体mAP下降提供了更细的解释。

当前结果不能支持：

- 已经完成真实TensorRT INT8部署；
- 已经测得Jetson Orin的FPS、延迟、功耗或能量/帧；
- G1+G5是全局最优配置；
- 目标级选模已经显著优于传统方法；
- RUOD-R结果已经推广到VisDrone或其他检测器。

## 关键名词用大白话解释

### RUOD-R

当前工程使用的水下目标检测数据目录名称。图片配有类别和真实目标框，便于判断模型到底漏掉了哪个目标。它不是模型，也不是量化方法；具体数据版本以`config/gate0.json`指向的数据和冻结清单为准。

### YOLO11n

当前使用的轻量目标检测模型。输入一张图，输出目标类别、位置和置信度；`n`表示nano小模型。

### FP32

普通的高精度浮点计算版本。它是当前实验中的参考版本。

### W8A8

`W8`表示权重用8位表示，`A8`表示中间激活值用8位表示。数字更省空间、更适合边缘设备，但会带来舍入和截断误差。

本工程实际干预的是分组中的Conv2d卷积：对其权重和输入激活做Q/DQ。“全W8A8”是全部纳入实验的卷积开启该模拟，并不是网络里每一种运算都变成INT8。当前恢复组保持FP32，不是FP16；未来Orin计划恢复为FP16，因此必须重新验证。

### PyTorch Q/DQ模拟

在PyTorch模型中插入Quantize和Dequantize操作，模拟量化前后的数值变化。它可以用来研究“量化误差会不会让目标消失”，但通常仍由普通浮点算子完成，所以不能直接当成Jetson真实INT8速度和功耗结果。

### TensorRT INT8

NVIDIA的部署工具可以构建使用真实INT8内核的推理引擎。它会受到层融合、校准、硬件和精度约束的影响；即使引擎名叫INT8，也可能混有FP16/FP32运算。Gate 0.5要核查实际执行精度，再检查PyTorch模拟现象能不能迁移到这里。

## G1到G8是什么

G1到G8不是8个模型，而是把YOLO11n的不同网络层分成8组：

| 分组 | 网络位置 | 通俗作用 |
|---|---|---|
| G1 | stem和早期backbone，模型0–2层 | 读取边缘、纹理和早期细节 |
| G2 | backbone中前段，模型3–4层 | 继续提取局部结构 |
| G3 | backbone中后段，模型5–6层 | 形成更深的目标特征 |
| G4 | 深层backbone、SPPF/PSA，模型7–10层 | 结合深层语义和上下文 |
| G5 | neck自上而下路径，模型13、16层中的卷积 | 把深层信息传给高分辨率特征 |
| G6 | neck自下而上路径，模型17、19、20、22层中的卷积 | 再次融合不同尺度信息 |
| G7 | P3小目标检测分支 | 主要处理较小尺度目标 |
| G8 | P4/P5和DFL分支 | 主要处理较大尺度目标和框回归 |

目前G1的信号最强，G5作为组合候选有一定增量；这不等于G1是唯一物理根因，也不等于G1+G5已经是最优工程方案。

这些层号是代码中的`model.<编号>`，从0开始；分组对象仅为卷积。精确成员见`artifacts/manifests/module_inventory.json`与`src/gate0.py`中的`group_for_conv`，不是凭上面的功能类比给层贴标签。

## 接下来怎么做

### Gate 0.5：先在真实Orin上做小规模真实性检查

截至 2026-10-21，已通过 SSH 连接真实 Orin NX 8GB，确认 Ubuntu 20.04.6、Jetson Linux 35.3.1、TensorRT 8.5.2.2。原六个配置完成构建和固定单图执行，另存完整 q_only_G1 修复候选完成实际精度审计与单图检查；另存修复 q_all 仍构建失败。最新 DFL 六节点 Conv 输出边界仍为 NONE 成功、OBEY 同类断言失败，无引擎或推理，详见[36](36_Gate05_DFL卷积输出边界定位.md)。成功四维输出和旧八节点三维数组在明确对应后字节相同；这次概率输入相同，与更早 logits/概率跨边界对照的证据应分开。实际 Conv 输出 FP32，不能将构建成功当成完整数值正确性或 Gate 通过。此前全部对照与原始拓扑数值偏差继续保留。本次未升级、刷机或重试完整图；监护完成不等于两组构建均通过。第一阶段仍需要回答：

> PyTorch模拟中看到的“目标消失—恢复模块—同一目标回来”，在真实TensorRT上是否还存在？

后续真实性评估路线如下，启动前需完成当前完整图兼容性、参考可比性和验收协议；当前不直接重试全图、启动恢复矩阵或运行 150 张图片：

1. 已确认系统可运行，保留当前软件环境和模型哈希。
2. 当前通过连接电脑的 USB 网络使用 SSH；后续运行继续记录启动编号及断连情况。
3. 已记录 Orin、Jetson Linux、TensorRT、输入尺寸和 batch size。15W 模式查询有非管理员 EMC 读取权限提示，完整特权查询未重跑，报告保留这一限制。
4. 复制YOLO11n模型、独立校准数据和预先固定的约100–150张RUOD-R验证图片；保存文件清单和哈希。不得一边看结果一边换图、改阈值或挑恢复模块，也不能将旧Holdout再次包装成新方法的独立确认集。
5. 在同一设备、同一输入尺寸和同一功耗模式下构建五个engine：FP16、全INT8、G1恢复、G1+G5恢复、G1+G2恢复。
6. 用engine inspector或等价工具检查精度约束真的生效，不能只看engine构建成功。
7. 对五个engine运行同一批图片，使用和Gate 0相同的目标级匹配规则，记录新增漏检、救回和附带漏检。实机的新增漏检首先相对本机FP16定义，另检查FP32到FP16自身的变化；不要与原模拟FP32口径直接混加。
8. 若要验证实机“双向同目标”，必须额外构建第六个engine：仅G1用INT8，其余FP16，作为`q_only:G1`破坏侧。前五种配置只能验证恢复，不能单独得出双向归因。G1+G5若也要双向验证，还需要它自己的q_only配置。
9. 如果全INT8没有新增漏检，或者恢复G1不能让相同目标回来，就记录不复现或证据不足，先核对校准、分组映射和匹配口径，不能伪造成功；若精度约束无法落实，记为部署验证未完成，而非机制失败。如果现象复现，再进入Gate 1。

开始固定数据集评估前还要解决原完整数值护栏及浮点/融合参考可比性，并冻结通过/失败/不确定的判据，不能看完结果再定门槛。单图流水线护栏已在运行前记录于 `artifacts/gate05/20261018_fp16/checkpoint.json`，它不替代数据集判据。此阶段至少保存环境记录、校准/测试清单、engine构建及实际层精度记录、逐目标CSV、同目标破坏—恢复案例和一份结论报告。当前 FP16、INT8 和按组精度请求的构建及格式审计均已有实现；严格整数证据缺口和完整数值迁移仍待解决。

这一阶段只做真实性检查，不急着写完整的FPS、功耗和能量结论。

### Gate 1：用VisDrone检查跨数据集

Gate 1的主基准改用非水下的VisDrone。查看结果前先固定：数据划分、模型、输入尺寸、量化方式、候选生成规则、传统基线、无标签基线、随机对照和停止条件。

最小流程是：

1. 建立FP32、FP16和全W8A8基线；
2. 找到FP32命中而W8A8漏检的小目标；
3. 完成G1–G8的双向干预；
4. 冻结目标级归因和恢复评分；
5. 在独立Holdout上验证；
6. 再判断目标级信息是否真的比传统方法增加了价值。

### Gate 2：测真实部署收益

候选方案冻结后，才在Orin上系统测量：

- 端到端和纯模型延迟；
- P50/P95延迟；
- 吞吐和显存；
- 固定功耗模式下的平均功率；
- 能量/帧；
- FP16/INT8边界转换开销；
- G1、G1+G5、G1+G2的精度—速度—能耗折中。

如果混合精度没有比FP16更快，或者实际大量层隐式回退到FP16，就不能声称它有部署Pareto优势。

## 现在最应该做的下一件事

完整参考分歧已通过[29](29_Gate05_完整参考数值分歧定位.md)定位，狭义诊断参考协议没有替换原 Gate 0 参考或原护栏。全 INT8 修复候选仍为 native 格式筛选失败，见[30](30_Gate05_全INT8修复候选验证.md)。从[DFL 四格](34_Gate05_DFL原始拓扑与约束对照.md)、[Softmax 后切片](35_Gate05_DFL_Softmax邻接定位.md)到最新[六节点 Conv 输出](36_Gate05_DFL卷积输出边界定位.md)，OBEY 仍同类失败；局部失败不需要 code_clip 派生拓扑、显式 Softmax 或末端 Reshape。它没有确定完整失败节点，NONE 数组一致也不能替代完整兼容性与数值迁移；原始 NONE 的严重数值偏差保留。

下一步建议另冻结一个有限 pair，只旁路权重 Q/DQ，让 Conv 直接使用原始 FP32 权重 initializer，保留同一概率输入与激活 Q/Clip/DQ；先不同时改两条精度路径。这样没有新增尺度或重解释权重尺度，但权重量化数学语义已经改变，必须仅为该候选建立自己的新 CPU 参考，不要求旧全量化字节等价，也不能称为等价修复。NONE/OBEY 各一次、保留解析约束与实际层审计，可检查显式权重 QDQ 分支在该局部失败中的作用；源权重为 FP32 不保证最终内核采用 FP32，仍需查实际格式。激活路径旁路仅是后续互补备选，不自动增加实验。当前只有[未执行建议](artifacts/gate05/20261020_dfl_conv_output_native/next_control_plan.json)，不运行新上游、完整图、恢复矩阵或数据集，也不 reset parser。

当前诊断链包含完整 q_only_G1 实机候选、固定图 GT、单/双 Conv、DFL 原始/修正四格、Softmax 切口以及本轮 Conv 输出边界。六节点精确来源、一次新 CPU 与四维 expected 的纯形状转换记录位于 `artifacts/gate05/20261020_dfl_conv_output_probe/`；本轮 89 份原始 native 文件、四维/三维保存数组对应和编译失败记录位于 `artifacts/gate05/20261020_dfl_conv_output_native/`，最新入口为[36_Gate05_DFL卷积输出边界定位.md](36_Gate05_DFL卷积输出边界定位.md)。原 72 Conv fixture、旧 DFL 与全部原失败继续保留。

在进入数据集评估前，还须保留原完整 PyTorch/ORT 失败作为独立问题，审查匹配的浮点/融合对照，处理七个深度卷积严格整数证据缺口，并冻结数据集验收规则。现有固定图用于调试，不代替独立精度验证。
