## 最新工程结果

- 随机初始化 YOLO11n 使用4张合成训练图和2张合成 training_val 图，实际完成1轮 CPU 训练、2次 SGD 与2次 EMA 更新。
- 忽略背景区域实际进入 TAL 分类损失；两批记录的正 anchor 为9、10，屏蔽的忽略背景 anchor 为67、98。分类屏蔽不代表共享参数总梯度不变，也不代表精度收益。
- Dataset、criterion/Trainer、FP32 hook 共119项测试通过。最终采用 attempt_03，实际固定单线程；前两次尝试及线程诊断保留。
- 保存入口在普通框架 half 序列化前捕获 live FP32 EMA。独立 CPU 进程以受限 state-only 加载并按架构重建，解析合成输入的输出 exact。仅保存推理状态，不包含优化器恢复状态，也未资格验证 CUDA 捕获。
- 本轮任务 AP 状态为 `SMOKE_NO_TASK_AP`。此前 AP/AR 的32组合成原生对照不等于完成真实数据 AP。

原30轮候选和旧全 FP16 检查保持 `FAIL_FIXED_TOLERANCES`；Gate0.5 原数值护栏保持 `FAILED_UNCHANGED`。真实 ignore-aware/CUDA 训练、独立真实数据 AP、科学 Gate1、后续导出与板端资格、速度功耗仍待分别验收。

## 复现与证据范围

Git 代码树不直接放入模型权重、引擎和数值数组；这些项目产物通过同一私有仓库的 Release 附件保存，具体文件以[附件索引](发布清单/release_assets.json)为准。发布内容排除原始训练/验证/确认集、外部下载的预训练模型、虚拟环境、下载的运行时与依赖包、临时 SSH 授权或凭据。原实验中依赖排除输入或原运行环境的命令不能只凭本仓库直接全量重跑；先核对对应合同、环境记录和发布清单。不要把历史运行脚本当作自动执行队列。

Release 中的 filtered archive 仅包含筛选后的证据成员。原始 manifest 可能引用排除文件；保留原 manifest 不意味着附件仍是原目录的完整副本，也不意味着能整包通过历史校验。发布完整性应先按[纳入文件清单](发布清单/included_files.jsonl)和[附件索引](发布清单/release_assets.json)复核，原始实验检查则需要另外满足其全部输入要求。

原训练源码、保存输出的一致性、合成测试、官方评测语义、模型科学资格和设备性能是不同证据层次。使用报告时应保留其样本范围、阈值、时点和失败状态。
